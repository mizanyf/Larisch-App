# ARCHITECTURE — Larisch Flutter App

Dokumen ini menjelaskan arsitektur teknis, struktur folder, skema database SQLite lokal (**Drift**), rumus perhitungan keuangan, serta format **Backup & Restore JSON lokal** untuk `larisch_app`.

---

## 1. Tech Stack

| Layer | Teknologi | Alasan |
| :--- | :--- | :--- |
| **UI Framework** | Flutter (Dart `^3.13.4`) | Cross-platform Android & iOS, kontrol penuh terhadap custom fintech UI |
| **Local Database** | `drift` + `drift_flutter` (SQLite) | Relational, type-safe, reactive stream, query filter/agregasi cepat, 100% offline |
| **State Management** | `flutter_riverpod` | Reactive terhadap stream database Drift, modular, mudah di-unit-test |
| **Navigation** | `go_router` | Mendukung redirect otomatis Onboarding vs Beranda + `ShellRoute` untuk 4 tab |
| **Charts** | `fl_chart` | Ringan dan fleksibel untuk grafik tren arus kas di layar Laporan |
| **Formatting** | `intl` | Format mata uang Rupiah (`Rp 23.500.000`) dan tanggal lokal Indonesia (`id_ID`) |
| **Backup/Restore** | `file_picker`, `share_plus`, `path_provider` | Export/Import file `.json` langsung di perangkat tanpa server/cloud |

## 3. Skema Database Lokal (SQLite / Drift)

Seluruh nominal uang disimpan sebagai **`INTEGER` (Rupiah utuh, tanpa desimal)**. Tanggal disimpan sebagai **`DateTime` (epoch/ISO8601 lokal)**.

### 3.1 Tabel `business_profiles` (1 baris aktif)
| Kolom | Tipe | Keterangan |
| :--- | :--- | :--- |
| `id` | `INTEGER PK` | Default `1` |
| `businessName` | `TEXT NOT NULL` | Nama usaha (misal: `Kedai Kopi Budi`) |
| `businessType` | `TEXT` | Jenis usaha opsional (misal: `Kuliner & Minuman`) |
| `onboardingCompleted` | `BOOLEAN NOT NULL` | Default `false`, menjadi `true` setelah setup selesai |
| `createdAt` | `DATETIME NOT NULL` | Waktu pembuatan |
| `updatedAt` | `DATETIME NOT NULL` | Waktu terakhir diubah |

### 3.2 Tabel `cash_accounts` (3 akun kas manual)
| Kolom | Tipe | Keterangan |
| :--- | :--- | :--- |
| `id` | `TEXT PK` | `'cash'` (Tunai), `'qris'` (QRIS), `'bank'` (Rekening Bank) |
| `name` | `TEXT NOT NULL` | `'Tunai'`, `'QRIS'`, `'Rekening Bank'` |
| `initialBalance` | `INTEGER NOT NULL` | Saldo awal manual (default `0`) |
| `sortOrder` | `INTEGER NOT NULL` | Urutan tampilan (`1`, `2`, `3`) |
| `updatedAt` | `DATETIME NOT NULL` | Waktu terakhir diubah |

### 3.3 Tabel `categories`
| Kolom | Tipe | Keterangan |
| :--- | :--- | :--- |
| `id` | `INTEGER PK AUTOINCREMENT` | ID kategori |
| `name` | `TEXT NOT NULL` | Nama kategori (misal: `Bahan Baku`, `Penjualan Kedai`) |
| `type` | `TEXT NOT NULL` | `'income'` atau `'expense'` |
| `iconKey` | `TEXT NOT NULL` | Nama key ikon Material/custom |
| `isDefault` | `BOOLEAN NOT NULL` | `true` untuk kategori bawaan sistem |
| `isArchived` | `BOOLEAN NOT NULL` | Soft-delete jika kategori sudah pernah dipakai transaksi |

### 3.4 Tabel `transactions`
| Kolom | Tipe | Keterangan |
| :--- | :--- | :--- |
| `id` | `INTEGER PK AUTOINCREMENT` | ID transaksi |
| `type` | `TEXT NOT NULL` | `'income'` atau `'expense'` |
| `amount` | `INTEGER NOT NULL` | Nominal Rupiah (`> 0`, divalidasi di domain & UI) |
| `accountId` | `TEXT NOT NULL FK` | Referensi ke `cash_accounts.id` (`'cash'`, `'qris'`, `'bank'`) |
| `categoryId` | `INTEGER NOT NULL FK` | Referensi ke `categories.id` |
| `note` | `TEXT` | Catatan transaksi opsional |
| `transactionDate` | `DATETIME NOT NULL` | Tanggal & jam transaksi |
| `createdAt` | `DATETIME NOT NULL` | Waktu dibuat |
| `updatedAt` | `DATETIME NOT NULL` | Waktu terakhir diedit |

## 4. Rumus Perhitungan Keuangan (Single Source of Truth)

Agar angka di **Beranda**, **Transaksi**, dan **Laporan** selalu 100% konsisten, seluruh saldo **dihitung secara dinamis** dari `initialBalance` dan tabel `transactions` (tidak menyimpan cache saldo terpisah yang rawan tidak sinkron):

1. **Saldo per Akun Kas (`accountId`):**
   $$\text{Saldo}(a) = \text{initialBalance}(a) + \sum_{\text{income}, a} \text{amount} - \sum_{\text{expense}, a} \text{amount}$$
2. **Total Saldo Kas:**
   $$\text{Total Saldo Kas} = \text{Saldo}(\text{Tunai}) + \text{Saldo}(\text{QRIS}) + \text{Saldo}(\text{Rekening Bank})$$
3. **Laba Bersih (Periode Terpilih $P$):**
   $$\text{Laba Bersih}(P) = \sum_{\text{income} \in P} \text{amount} - \sum_{\text{expense} \in P} \text{amount}$$
4. **Margin Laba (Periode $P$):**
   $$\text{Margin}(P) = \begin{cases} \frac{\text{Laba Bersih}(P)}{\text{Total Pemasukan}(P)} \times 100\% & \text{jika Total Pemasukan}(P) > 0 \\ 0\% & \text{jika Total Pemasukan}(P) = 0 \end{cases}$$

## 5. Format File Backup & Restore Lokal (`.json`)

File backup lokal disimpan dengan nama `larisch_backup_YYYYMMDD_HHmm.json`:

```json
{
  "app": "Larisch",
  "schemaVersion": 1,
  "exportedAt": "2026-11-24T12:00:00.000",
  "businessProfile": {
    "businessName": "Kedai Kopi Budi",
    "businessType": "Kuliner & Minuman"
  },
  "cashAccounts": [
    { "id": "cash", "name": "Tunai", "initialBalance": 5000000 },
    { "id": "qris", "name": "QRIS", "initialBalance": 3000000 },
    { "id": "bank", "name": "Rekening Bank", "initialBalance": 9300000 }
  ],
  "categories": [
    { "id": 1, "name": "Penjualan Kedai", "type": "income", "iconKey": "store", "isDefault": true }
  ],
  "transactions": [
    {
      "id": 1,
      "type": "income",
      "amount": 385000,
      "accountId": "qris",
      "categoryId": 1,
      "note": "Penjualan Kedai",
      "transactionDate": "2026-11-24T14:20:00.000"
    }
  ]
}
```

### Aturan Restore Aman
- Validasi `app == "Larisch"`, `schemaVersion`, dan integritas referensi `accountId`/`categoryId` sebelum menulis ke database.
- Eksekusi restore **wajib di dalam 1 transaksi SQLite (`db.transaction(...)`)** sehingga jika terjadi error di tengah jalan, data lama otomatis di-rollback dan tidak rusak.
